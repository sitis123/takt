# Архитектура

## Принцип

Один прикладной слой `Takt`, три тонких адаптера. Веб, бот и CLI не содержат бизнес-логики: они только принимают ввод и показывают результат `services.py`. Это позволяет менять интерфейс, не переписывая правила работы со счетами и задачами.

```
        веб (web/)      Telegram (bot.py)      консоль (cli.py)
              \               |                    /
               \              |                   /
                ---> services.py (Takt) <--------
                          |
          ---------------------------------
          |        |       |       |      |
       db.py    parser.py ai.py render.py money.py
          |
       SQLite ~/.takt/takt.db + ~/.takt/out/*
```

## Слои

| Слой | Ответственность | Что не делает |
| --- | --- | --- |
| `config.py` | читает окружение, создаёт каталоги | не хранит секреты в файлах |
| `db.py` | SQLite, транзакции, события, напоминания | не знает про форматы документов |
| `parser.py` | детерминированный разбор текста и таблиц | не обращается к сети |
| `ai.py` | опциональные AI-вызовы: поля, фото, голос | не принимает решений о статусе |
| `services.py` | счета, акты, импорт, задачи, отчёты, напоминания | не знает про HTTP и Telegram |
| `render.py`, `money.py` | печатные формы и суммы словами | не пишут в базу |
| `api.py`, `bot.py`, `cli.py` | адаптеры ввода/вывода | не дублируют логику |

## Данные

Основные таблицы: `clients`, `documents`, `tasks`, `reminders`, `events`, `settings`.

- `documents` хранит счёт и импорт таблицы; тип в поле `kind`. Статусы: `draft`, `sent`, `paid`, `done`.
- `payload` — JSON с реквизитами, путями к файлам и превью строк.
- `reminders` — отложенные сообщения с `due_at` и `sent_at`. Один раз отправленное напоминание помечается и не дублируется.
- `events` — журнал для веб-панели и отладки: что, когда и кем было сделано.

Все временные метки в ISO-формате UTC, сравнение строк работает без временных зон.

## AI как опция

AI не является обязательной зависимостью продукта:

- без ключа работает локальный парсер — продукт остаётся полезным;
- с ключом AI только улучшает извлечение полей, распознаёт фото и расшифровывает голос;
- ошибка AI не ломает создание счёта: сервис откатывается к локальному разбору.

Это важно для долгой жизни продукта: смена провайдера или рост цены на токены не убивает основной сценарий.

## Расширение

- Новый канал ввода: тонкий адаптер, который вызывает `Takt`.
- Новый тип документа: новое поле `kind` и функция в `services.py`, разметка в `render.py`.
- Новый тариф: лимиты в `settings` и проверка в адаптере, ядро не меняется.
- Планировщик: отдельный процесс вызывает `flush_reminders(sender)`, где `sender` — отправка в Telegram или другую систему.

## Границы

Продукт не является бухгалтерской системой и не заменяет юриста. Он готовит документы и напоминает о сроках; финальную проверку и подпись делает человек. Это честная и устойчивая позиция.
